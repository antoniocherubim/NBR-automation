# NBR-000 — Registro de fonte e referências normativas

## Objetivo

Criar um índice normativo v1 determinístico e validável que identifique a
fonte licenciada da ABNT NBR 12721 fornecida ao projeto e registre as
referências necessárias às regras planejadas no ROADMAP.

O índice deve responder, sem copiar conteúdo protegido: qual fonte, edição,
versão corrigida, seção e localização sustentam uma futura regra; qual é seu
tipo; e se ela está apenas indexada, formalizada ou implementada.

NBR-000 não implementa regras normativas. Ela cria somente o catálogo de
autoridade que tasks posteriores deverão citar.

## Contexto

O repositório público possui histórico sanitizado e não contém os bytes reais.
A fonte normativa é fornecida exclusivamente pela cópia local ignorada:

```text
inputs/private/normativa/ABNT NBR 12721-2006.pdf
```

O ID lógico público permanece:

```text
inputs/normativa/ABNT NBR 12721-2006.pdf
```

O SHA-256 autoritativo, presente em `SHA256SUMS`, no source manifest e no
inventário privado, é:

```text
76b3c72fd5934867305b2440c3af66ef79004c07496c436095516c3afdc05674
```

O ROADMAP registra a fonte como **ABNT NBR 12721:2006, segunda edição,
versão corrigida 3**, incorporando as erratas de 2007 e a Errata 3 de
19/01/2021. A menção a 2021 nos metadados não cria uma edição “NBR
12721:2021”.

O PDF é licenciado. Podem ser persistidos identidade, paths relativos,
digests, seções, localizadores, tipos, estados e paráfrases curtas. Cláusulas,
tabelas, figuras, formulários e trechos extensos não podem ser redistribuídos.

## Escopo

### 1. Registro normativo

Criar um módulo independente sob `src/nbr12721/normative/` com contratos
imutáveis e validação fail-closed para:

- identidade da fonte normativa;
- identidade estável de cada referência;
- seção normativa;
- página física do PDF e página impressa;
- tipo da referência;
- estado de formalização;
- notas concisas de edição/errata;
- links explícitos entre referência e fonte.

O módulo usa somente a biblioteca padrão e não importa PDF, OCR, XLSX,
geometria, UI, rede ou o mecanismo de fixtures privadas.

### 2. Identidade da fonte

Representar explicitamente:

- organização emissora: ABNT;
- designação: NBR 12721;
- ano: 2006;
- segunda edição;
- versão corrigida 3;
- erratas de 2007 e Errata 3 de 19/01/2021;
- ID lógico público, SHA-256 e media type;
- vínculo inequívoco ao `SourceArtifact` correspondente.

Datas usam ISO 8601 quando aplicável. Timestamp de geração, hostname e path
absoluto não entram no payload canônico.

### 3. IDs e referências

Cada entrada possui ID legível, estável e único derivado de componentes
normativos estáveis, nunca de posição na lista, timestamp ou estado local.

Cada entrada contém no mínimo:

- `id`;
- referência à fonte;
- designador exato de seção ou anexo;
- localizador de página;
- tipo controlado;
- estado controlado;
- descrição curta em linguagem própria;
- notas de edição/errata quando relevantes.

Referências cruzadas e múltiplas autoridades são estruturas explícitas, não
texto concatenado.

### 4. Página física e página impressa

- página física/PDF: posição 1-based verificável no arquivo fornecido;
- página impressa: rótulo exibido, separado e capaz de representar número,
  romano ou ausência legítima.

Ausência de página impressa é explícita e justificada; nunca recebe
silenciosamente o número da página física. Os localizadores devem ser
conferidos read-only na fonte materializada, sem parser novo.

### 5. Tipo e estado

Vocabulários fechados devem distinguir, no mínimo:

- definição/classificação;
- medição/delimitação;
- cálculo/distribuição;
- condição de aplicabilidade;
- quadro/formulário.

Estados mínimos:

- `indexed`: autoridade localizada, sem regra executável;
- `formalized`: contrato/regra formal existente e referenciado;
- `implemented`: implementação existente e referenciada.

As entradas criadas nesta task ficam `indexed`, salvo evidência anterior
rastreável. `formalized` exige referência ao artefato formal; `implemented`
exige referência normativa e à implementação.

### 6. Cobertura inicial

Cobrir, sem transcrever:

- prefácio e identificação da edição/versão corrigida;
- seção 3.7 e subdivisões relevantes;
- seções 3.7.2.1 e 3.7.2.2, inclusive os papéis distintos de vagas;
- seções 3.7.3 e 3.7.4;
- seção 3.14;
- seções 5.2 a 5.6;
- seção 5.7 e 5.7.1 a 5.7.3 quando aplicáveis;
- seções 5.8.1, 5.8.2 e 5.8.3;
- autoridade que distingue IV-B de IV-B-1;
- Anexo A e Quadros I, II, IV-B e IV-B-1.

Cobertura significa localizar e classificar autoridade, não implementar ou
reproduzir seu conteúdo.

### 7. Schema e serialização

Criar JSON Schema Draft 2020-12 e validação de produção equivalente em Python
stdlib. O contrato deve:

- usar `schema_version = 1`;
- rejeitar campos desconhecidos;
- impor formatos, enums, campos obrigatórios e unicidade;
- separar fonte, entradas e localizadores;
- usar regex compatível com ECMA-262;
- serializar UTF-8 de forma byte-estável, com ordem canônica e newline final.

Artefatos preferenciais:

```text
registries/normative-reference-index.json
schemas/normative-reference-index-v1.schema.json
```

## Boundary de implementação

```text
SourceArtifact lógico + cópia privada verificada
                  |
                  v
identidade da edição/erratas
                  |
                  v
referências (seção + página PDF + página impressa)
                  |
                  v
```

metadata pública; ele não lê configuração XDG nem conhece o store externo.

## Critérios de aceitação

1. A fonte usa o ID lógico, digest e media type dos manifests públicos.
2. A identidade diferencia 2006 de Errata 3/2021 sem inventar edição 2021.
3. Toda cobertura obrigatória foi conferida na cópia privada imutável.
4. Cada entrada possui ID único, fonte, seção, localizador, tipo, estado e
   descrição concisa.
5. Página PDF e página impressa são semanticamente distintas.
6. Ausência de página impressa é explícita e justificada.
7. IDs duplicados, fonte desconhecida, seção vazia, página inválida, booleano
   como inteiro, enum ou campo desconhecido falham deterministicamente.
8. `formalized` e `implemented` exigem links rastreáveis; o baseline permanece
   `indexed`.
9. Schema e validação Python concordam nos casos cobertos.
10. Duas gerações equivalentes produzem bytes idênticos.
11. Payload não contém timestamps voláteis, paths absolutos ou hostname.
12. Nenhum conteúdo licenciado extenso aparece no índice, testes, docs ou logs.
13. Não há regra NBR, Quadro, PDF, OCR ou XLSX implementado.
14. Testes públicos não dependem do store privado.
15. Store, materialização, `SHA256SUMS` e manifests permanecem intactos.
16. Documentação distingue capacidade entregue de trabalho planejado.
17. Todos os gates passam offline.
18. Nenhuma operação controlada pelo operador é executada automaticamente.

Antes da pesquisa normativa:

```bash

python3 scripts/ci/validate-public-tree.py --candidate
```

Gates públicos finais:

```bash

PYTHONPATH=src:scripts/private-fixtures python3 -m unittest discover -s tests -p 'test_*.py' -v
python3 scripts/ci/validate-public-tree.py --candidate
git diff --check
git status --short --untracked-files=all
```

Testes focados cobrem ao menos:

- identidade da edição e digest;
- cobertura das seções obrigatórias;
- ID duplicado, fonte e seção inexistentes;
- página PDF zero, negativa ou booleana;
- página impressa ausente com e sem justificativa;
- tipo, estado e campo desconhecido;
- `formalized`/`implemented` sem links;
- round-trip e serialização byte-estável;
- schema incompatível;
- divergência do digest contra o source manifest;
- reconstrução sem writes nas fixtures;
- exemplos integralmente sintéticos.

A revisão deve reconstruir o índice independentemente, comparar bytes e
conferir uma amostra representativa de localizadores na fonte. Inspeção humana
é evidência de revisão, não autorização para criar parser PDF.
